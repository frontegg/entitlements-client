# FR-26219 — Workstream C · entitlements-client

Jira: https://frontegg.atlassian.net/browse/FR-26219
Cursor rule: `.cursor/rules/fr-26219-sdk-isolation.mdc`

This repo's job: `isEntitledTo` and every other SpiceDB read answer for exactly one Frontegg
instance, namespaced by that instance's schema prefix, and refuse to answer when the instance is
ambiguous or unknown.

## The cross-repo contract

```
prefix = "v_" + vendorId.replaceAll("-", "_")
         // 2f9c1a44-7b0e-4a1e-9f8a-1c2d3e4f5a6b  ->  v_2f9c1a44_7b0e_4a1e_9f8a_1c2d3e4f5a6b
         // SpiceDB identifier rules: ^[a-z_][a-z0-9_]{1,62}[a-z0-9]$ , 3-64 chars
type   = <prefix>/frontegg_feature | <prefix>/frontegg_tenant | <prefix>/frontegg_user
       | <prefix>/frontegg_permission | <prefix>/frontegg_non_linked_permission
       | <prefix>/frontegg_plan | <prefix>/frontegg_route | <prefix>/<rebacEntityType>
```

The prefix is ALWAYS derived from a vendorId proven by a vendor JWT or the authenticated request
context. Config may only declare *whether* to prefix. No `instances` configured means legacy
unprefixed data and must behave exactly like before.

Caveats are prefixed too — Step 0 settled D6 as **C1**, so the schema defines `<prefix>/targeting`,
`<prefix>/route_regex` and `<prefix>/active_at`.

## What landed

- **`SchemaNamespace`** — applies the prefix on the way in, strips it on the way out. A caller type
  containing `/` is rejected only once a prefix is actually being added, so a legacy caller whose
  own schema uses namespaced types is untouched.
- **`schema-prefix`** — derives `v_<vendorId>` and validates against SpiceDB's identifier rule with
  explicit character checks, not a regex.
- **`InstanceRegistry`** — validates at construction rather than per request, and rejects two
  instances resolving to the same prefix: colliding overrides, two vendorIds that normalise alike
  (`ACME-CORP` / `acme_corp`), or an empty prefix inside a populated `instances` list.
- **`resolveInstance`** — the four resolution rules, fail-closed.
- **Exceptions** — `UnknownInstanceException`, `InstanceIdRequiredException`,
  `InvalidObjectTypeException`.
- **Every read path namespaced** — four query strategies, both lookup builders, the batch feature
  path. Route cache keyed per prefix.
- **Public surface** — `instanceId` as a trailing options argument on all five methods,
  `readSchemaFor(instanceId)`, per-instance fallback config, `instanceId` on log lines.
- **G6 lint rule** — `eslint-rules/require-namespaced-object-type.js`, type-aware, wired as `error`.

## Isolation suite (plan section 10.2)

`src/spicedb/spicedb-entitlements.client.isolation.spec.ts`, fixture in `isolation.spec-helper.ts`.
Runs against a real SpiceDB; skipped unless `SPICEDB_TEST_ENDPOINT` is set, so CI without a SpiceDB
stays green. `.github/workflows/_isolation.yaml` runs it on every PR and `pre-release` waits on it,
so a cross-instance leak blocks the release.

```bash
spicedb serve --grpc-preshared-key "$(openssl rand -hex 16)" --datastore-engine memory \
  --grpc-addr :50051 --datastore-revision-quantization-interval 0s

SPICEDB_TEST_ENDPOINT=localhost:50051 SPICEDB_TEST_TOKEN=<same key> yarn test:isolation
```

## Notes / found while working

- `SchemaNamespace.type()` is the single chokepoint for G7; the lint rule keeps it that way.
- The lookup mappers echo the caller's own type string, so no `strip()` is needed on that path.
- **The isolation suite earned its keep during the PR split.** `InvalidObjectTypeException` extends
  `Error`, not `ConfigurationInputIsInvalidException`, so the rethrow guards did not cover it and a
  prefix escape was being answered with the fallback boolean instead of throwing. Nothing in the
  unit tests caught it. Any new exception that must not degrade to a boolean has to be added to
  both guards.
- `tsconfig.json` excludes specs, so `tsc --noEmit` passes while a spec fails to compile. Only
  `yarn test` proves the specs typecheck.
- SpiceDB serves reads from a quantized revision, so a write-then-read suite fails on a cold server
  and passes on a warm one. `beforeAll` waits for its own seed.
- `jest.spyOn` will not attach to the authzed promise client's bound methods. The fail-closed tests
  point a client at a dead port instead, so reaching SpiceDB at all would surface as a gRPC error.
